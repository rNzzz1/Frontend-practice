## Подробно

### Практика 1
Папка: `task1`

Что сделано:
- сверстана карточка товара
- подключены стили
- добавлена адаптивность под мобильный экран
- оформлена кнопка действия и базовая визуальная иерархия

Что нового по сравнению с нулевой точкой:
- чистый HTML + CSS без JavaScript и сервера
- первый статический интерфейс магазина

### Практика 2
Папка: `task2`

Что сделано:
- поднят сервер на `Express`
- реализован CRUD для товаров: `POST`, `GET`, `GET by id`, `PATCH`, `DELETE`
- добавлен интерфейс управления товарами
- подключен `fetch` для работы фронтенда с API
- сделано модальное окно редактирования товара

Что нового:
- переход от статической страницы к клиент-серверной схеме
- данные теперь изменяются через API, а не вручную в HTML

### Практика 3
Папка: `task3`

Что сделано:
- реализован REST API для пользователей
- поддержаны методы `GET`, `POST`, `PUT`, `PATCH`, `DELETE`
- добавлена работа с JSON через `express.json()`
- подготовлены отчеты по локальному и внешнему API в папке `report`

Что нового:
- отдельный API-слой без фронтенда
- работа уже не с товарами, а с сущностью `users`

### Практика 4
Папка: `task4-5`

Что сделано:
- собран клиент на `React`
- реализован каталог товаров
- React-клиент получает данные с backend API магазина
- добавлены карточки товаров с изображениями, ценами, остатком и рейтингом

Что нового:
- переход с обычного HTML/JS на компонентный фронтенд
- фронтенд и backend начали работать как отдельные части одного приложения

### Практика 5
Папка: `task4-5`

Что сделано:
- расширен REST API
- подключен `Swagger`
- описаны маршруты через Swagger-аннотации
- добавлена страница документации `/api-docs`

Что нового:
- API стало самодокументируемым
- появилась удобная проверка маршрутов через Swagger UI

### Практика 6
Папка: отсутствует

- в текущем репозитории отдельной реализации практики 6 нет
- если нужна, ее лучше добавлять отдельной папкой `task6`

### Практика 7
Папка: `task7`

Что сделано:
- регистрация и вход пользователя
- отдельная страница авторизации
- проверка логина и пароля
- после входа идет переход на сайт магазина
- пароль не хранится открытым текстом, а хешируется
- реализован CRUD для товаров

Что нового:
- появилась аутентификация
- добавлена защита хранения пароля через хеширование и соль

### Практика 8
Папка: `task8`

Что сделано:
- вход переведен на `JWT`
- добавлен защищенный маршрут `GET /api/auth/me`
- все маршруты товаров защищены токеном
- фронтенд хранит `accessToken` и использует его в запросах

Что нового:
- сервер начал выдавать токен после логина
- доступ к API теперь зависит от наличия валидного JWT

### Практика 9
Папка: `task9`

Что сделано:
- добавлен `refreshToken`
- реализован маршрут `POST /api/auth/refresh`
- включена ротация refresh-токенов
- фронтенд умеет обновлять сессию без повторного ввода логина и пароля

Что нового:
- сессия стала двухуровневой: `accessToken` + `refreshToken`
- пользователь может продолжать работу даже после истечения access-токена

### Практика 10
Папка: `task10`

Что сделано:
- реализована фронтенд-часть на `React`
- токены хранятся на фронтенде
- клиент работает с backend API магазина
- подключен `axios` для запросов к API
- сохранена логика работы с каталогом товаров из прошлых практик

Что нового:
- акцент сместился на клиентскую часть
- работа с токенами вынесена на фронтенд
- backend из 9-й практики стал основой для React-клиента

### Практика 11
Папка: `task11`

Что сделано:
- добавлены роли `user`, `seller`, `admin`
- реализован доступ по ролям `RBAC`
- `user` может только смотреть каталог
- `seller` может смотреть, создавать и изменять товары
- `admin` может дополнительно удалять товары
- сделаны отдельные маршруты проверки ролей:
  - `/api/products/role`
  - `/api/product/role`
  - `/api/products/admin/role`
  - `/api/product/admin/role`

Что нового:
- доступ теперь определяется не только токеном, но и ролью пользователя
- появилась полноценная авторизация по ролям
